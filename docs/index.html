What is Eulerian Video Magnification?

Eulerian Video Magnification (EVM) is a computer-vision technique from MIT (Wu, Rubinstein, Freeman, Durand, Guttag; SIGGRAPH 2012) that makes tiny temporal changes in video visible. Classic examples: the pulse of blood under skin, the breathing of a sleeping infant, and small mechanical vibrations. Unlike Lagrangian methods that track features, EVM treats each pixel as a time series, applies a temporal bandpass, amplifies the band of interest, and reconstructs the video.

This site is a full open-source CUDA implementation of that pipeline — color (pulse) magnification with an ideal bandpass and motion magnification with a Laplacian pyramid + IIR bandpass — with demos, benchmarks, and writeups. It ports the MIT reference from MATLAB to raw CUDA C++ and achieves a ~1,280× motion compute-only speedup (~225× including host-device transfers) over a Python/NumPy baseline on an NVIDIA H100, with output validated against the Python baseline within RMSE 0.01.

Method

Every EVM variant follows the same four-stage pipeline. Each stage maps to one or more CUDA kernels, with the entire pipeline running device-resident: 

input video (T frames, H x W, RGB uint8)
   |
   1. COLOR    BGR u8 -> NTSC YIQ float (per-pixel matrix multiply)
   2. SPATIAL  Gaussian downsample (color) OR Laplacian pyramid (motion)
   3. TEMPORAL Bandpass filter along time (FFT / Butterworth / IIR)
   4. AMPLIFY  Multiply by alpha, add back, render to RGB
   |
output video (magnified)

The port validates against the Python baseline (evm/), which is itself validated against MIT's published output videos. Per-kernel tolerances range from 1e-6 (pure arithmetic) to 1e-4 (cuFFT), with end-to-end RMSE held below 0.01. See DESIGN.md for the kernel-by-kernel mapping.

Architecture

  • Device-resident pipeline — entire clip staged to GPU once; 50+ kernel launches with zero per-frame transfers
  • Batched spatial kernels — grid.z = M collapses ~35,000 launches into ~50
  • Templated FP16 storage — same spatial kernels for FP32/FP16; dense half smem + float MAC
  • cuFFT plan caching — eliminates per-call autotuning overhead
  • 92 tests — every kernel validated against the Python oracle, including MIT reference comparison

No PyTorch, no CuPy, no Numba. Every kernel is hand-written CUDA C++ with pybind11 bindings.
